Dialog semantic checklist for implementation

  • Use a real modal/dialog primitive in production; this prototype intentionally shows static cards only.
  • Move focus to the dialog heading or first invalid field on open, and return focus to the invoking control on close.
  • Make the background inert while the modal is open and provide Escape/cancel behavior only where it is safe.
  • Connect validation errors to affected fields and keep recovery actions keyboard reachable.

Prototype annotations

  • Related Section 13 IDs: Q-015, Q-020, Q-021.
  • Dialog cards are static pattern examples, not live modal implementations. Production modals must trap focus, make background content inert, use Escape only where safe, and return focus to the invoking control.
  • Color schema values remain textual so the control is not color-only.
  • State behavior details are outside the UI frame: activation loading starts after submit, guards duplicate submit, keeps focus inside the modal pattern, and announces "Activating..."; success, error, and permission states return focus to the relevant recovery control.
  • Color Schema includes invalid hex, disabled unchanged/invalid Apply rationale, and successful apply confirmation examples.
