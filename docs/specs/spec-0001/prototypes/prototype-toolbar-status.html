Prototype annotations

  • Related Section 13 IDs: Q-019, Q-020, Q-021.
  • Toolbar actions require accessible names and should not duplicate every menu item.
  • Status feedback is persistent enough to read and uses text plus semantic placement.
  • State behavior details are outside the UI frame: trigger, recovery, focus, and announcement rules follow mockups.md Section 5.3 and are mapped by status level during implementation.
  • The disabled Calculate affordance is a focusable explanation pattern, not an actionable command.
